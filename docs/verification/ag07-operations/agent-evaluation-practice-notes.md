# Agent评测实践补充：业务目标、轨迹与最终状态

日期：2026-10-27。参考用户粘贴全文的[《Agent评测漫谈——由浅入深讲解Agent评测》](https://mp.weixin.qq.com/s/gZKWRqznB8sNBFf69fBIvw)。微信原页面读取失败且浏览器站点策略拦截，本页依据用户提供正文；未读取文中图片，不补猜图片中的分层或数据。与[白皮书映射](agent-evaluation-alignment.md)配套。以下项目规则是我们的落地设计，未修改AG07 r1、原质量金标或AG06性能延期决策。

## 采用的方法及边界

文章把评测对象扩展到模型、系统、工具和流程的组合，要求同时看结果、过程、效率和风险；通过任务层指标连接业务价值与底层能力。客观检查和主观判断互补，主观标准需要先统一人评口径，再校准自动裁判。先从核心场景和好坏案例形成迭代闭环，避免起步即建设复杂平台。长程任务应核实执行轨迹和环境最终状态，不能仅凭回答文字判断成功。

这些方法用于改进本项目的评测解释力，不照搬文章中的一致率、案例成绩或框架选择。文章的85%/90%示例不是本项目门槛，单个自动裁判也不构成人人一致或人机一致的证据。

## 业务目标如何落到可检查的任务

|用户业务目标|任务层成功标准|过程证据|权威结果|限制|
|---|---|---|---|---|
|找到符合条件的门店/套餐|推荐对象满足明确的地点、价格、人数等条件；条件不足先澄清|意图、已知对象、限制、检索参数与当时工具结果|后端真实对象及有效业务字段|不以点赞/留存或模型知识题分数推断检索质量|
|按最新要求购买|最终确认的对象、数量及金额正确，仅写一次|纠正覆盖旧事实、旧确认失效、新授权、实际工具发送|执行键回执与唯一订单行|无授权不写；调用超时不能当未写而重新下单|
|暂停后继续处理|待办和最新限制保留，恢复后重新检查必要授权|暂停/恢复事件、任务关联、恢复前后状态|持久停点和当前任务终态|恢复不直接执行业务，重启不复活旧确认|
|知晓实际处理结果|回复忠实区分成功、失败、处理中、待核查|同轮实际回答与UI状态、关联工具回执|原键核查结果|回答流畅不抵消错误业务状态|

现阶段不声称这些任务指标已证明转化率、留存或用户满意度提升。业务收益需要另行采集适当数据，不能由技术指标直接推导。

## 最小数据结构与评分职责

- Task：固定输入、初始环境、对象归属、预期行为、禁止副作用与检查项ID，引用已有AG05资产；不另建相互冲突的金标。
- Trial：一次实际执行，绑定Task、源码、配置、环境及独立运行身份；历史重试不增加唯一任务分母。
- Trace：可观测动作、路由、状态转移、工具参数安全摘要、发送及回执；不要求或记录模型私有思维链。脱敏记录不足以复现时标明缺口。
- Outcome：该次执行结束时的权威业务状态。写入是否成功以业务表和原键回执判定，不以回复“成功”判定。
- Check：在固定证据上判断是、否、不可判；有依据的不适用另记理由。缺证据与未运行不计成功；安全失败不能被其他高分抵消。

评测驱动负责环境、预算、证据绑定和断言，Agent运行框架负责业务执行，两者故障分开记录。AG07-00结构守卫只检查同轮引用和记录完整性；后续动作还必须核对原始证据真实性、冻结的完整检查项及最终业务状态，不能拿结构守卫通过冒称任务成功。

## 客观检查优先，主观评测有明确边界

对象/权限、工具选择与参数、确认失效、唯一执行、持久状态和资源回收优先使用规则、契约、业务回读等确定性检查。推荐解释是否充分、表达是否易懂等开放项，可以由业务负责人定义少量可观察Rubric，保留正反例及允许的多条正确路径，不能规定唯一措辞或固定工具轨迹。

后续若引入自动裁判，先由业务负责人整理分歧，再让不同评测者在不互看答案的条件下标注同一小集合，分别报告一致、不一致、不可判及样本数。机器对照人工裁定时使用单独校准集合，保留混淆统计、误判安全案例及裁判版本。可信门槛需按用途另定，不在本轮自行采纳85%/90%。现在没有执行这项校准，不宣称已经实现自动主观评测。

## 小闭环接入AG07

1. 00引用已有十三类意图、开发/校准/历史留出、AG06有效证据范围，冻结必要检查层次；已使用的留出不改称首次盲测。
2. 02记录定位所需的外部可观察事实，并将重复事件、跨任务/跨轮、缺回执和未知写分开；指标汇总本身不产生Agent质量分数。
3. 03告警产生待排查案例，明确工程健康不代表质量已评；不自动捕获生产正文或调用模型Judge。
4. 08在原有界旅程内评价端到端、过程、安全和实际回复，效率只记录该旅程可获得的耗时、发送与真实usage；不恢复性能矩阵、不据此声明并发容量。
5. 09把失败归因于Agent、工具/服务、环境、驱动/标准或证据不足；修复案例纳入原定向回归，保留失败原记录。原始案例采集、清洗、检查、质检、归因均可由现有文件与脚本承载，不先建复杂平台。

最小种子集来自现有高频场景及历史硬失败，不为了“积累Bad Case”向生产开放可能越权或重复写的路径。线上抽样、AB、Skill生态评测、规模化主观裁判属于后续工作，须先明确隐私、成本、环境和门槛。

本补充为方法与实施映射，未运行新的Agent质量或性能评测，模型发送0。
