## 落入现有步骤的具体要求

以下是本项目的执行规则；以既有正确性要求为依据，合并进原00—09，不增加平行评测平台或新一轮矩阵。

1. **先确定必须验什么（00/09）。** 每个稳定caseId登记需求、入口、共享依赖、业务断言、原证据版本和复用原因；同义别名不重复计数。调用关系无法证明未受影响时不能复用。公共鉴权/准入/关闭/工具出口修改须扩展到其消费者，不能只测新增文件。
2. **先核评测数据（00/02/09）。** 冻结计划caseId集合、输入摘要、环境、规则版本；最终互斥状态为新验通过、新验失败、阻塞、未运行、合格复用、不适用，每项都有理由和证据。集合必须完整且无重复；执行尝试和逻辑场景分开计数。失败重试保存各轮记录，不拼接条件不同的结果。不可评、缺usage、缺回执不算通过或费用0。
3. **工具正确性看三处（02/08）。** 请求/轮次/对象关联、实际受信工具调用及返回、Spring权威回执与业务表一致；自然语言“已完成”或HTTP200不能独立证明提交。权限/确认/未知写边界即使主要流程失败，也必须保留对应独立安全断言，不能通过提前短路漏验。
4. **故障必须验证恢复（07）。** 同一F场景记录注入前业务基线、故障时保护行为和告警、恢复后原键回读及唯一执行、资源归还。原因分为产品、驱动、环境、外部依赖及证据不足；不把“恢复后健康接口200”当业务恢复。
5. **昂贵链路只跑必要组合（08/09）。** 先零模型定向守卫，再一次有界故障组合，最后一次必要真实UI旅程。同输入且未受影响的结果进入最终索引复用；只补失效场景。保留原8输入/1订单确认/40可观察模型发送上限，不能因研究文章扩大费用。
6. **运行指标与验收指标分开（02/09）。** 运维统计请求、工具和费用的实际分母；验收统计固定业务义务。两者不能互换。AG06性能失败与未测仍列债务，不混入AG07通过率，也不通过排除困难样本提高质量分数。

必需非延期义务有失败、阻塞或未运行即不能交付；统计比例只是辅助，不能取代逐项闭合。LLM评分、生产会话批量回放、自动改金标均不在本次r1范围。
