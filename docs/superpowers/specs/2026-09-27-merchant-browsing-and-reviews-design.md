# 商家浏览、分页与评价设计

## 背景

当前首页商家卡片使用静态文案，点击时只跳转到商家详情页，没有选择对应的后端商家。商家详情因此会复用上一次选择，或使用“清粥小菜”作为兜底，同时菜单可能为空。底部“商家”Tab 也直接指向详情页，没有承担商家发现入口的职责。详情页的“评价”仅有标签，没有交互和后端数据。

本次改造统一商家选择链路，并让首页、商家 Tab、菜单和评价全部使用后端数据库数据。

## 目标

- 首页标题改为“好店推荐”，不再出现距离、附近或定位准确度相关文案。
- 首页商家列表和“商家”Tab 均从后端分页读取商家；滚动到底自动加载下一页，直到数据加载完毕。
- 点击任何商家都以真实商家 ID 加载该商家的详情和菜单，不能复用旧商家或显示默认商家。
- “商家”Tab 首先展示商家列表，只有用户选择商家后才进入详情。
- 商家详情的“评价”支持只读分页展示，数据来自后端数据库。
- 保留现有购物车的跨商家切换确认规则。

## 非目标

- 不接入定位、地图或真实距离计算。
- 不允许用户发布、修改或删除评价。
- 不抓取或冒充互联网中的真实商家和真实用户评价。
- 不引入无限数据源；“持续加载”指按页追加，加载完后明确显示“已经到底了”。

## 导航与页面职责

### 首页

首页“好店推荐”使用动态容器替换三张静态卡片。进入首页后请求第 0 页，每页 4 家营业中的商家。用户接近页面底部时请求下一页，并把新商家追加到现有列表，不覆盖、不重复。

首页卡片展示商家名称、品类、起送价、配送费、预计配送时间和营业状态。移除距离标签与“添加地址后推荐更准确”等定位暗示，替换为“根据口味、热度与配送效率推荐”。

### 商家 Tab

底部导航的 `merchantFragment` 改为商家列表页。列表同样每页 4 家，拥有独立于首页的页码、加载状态和滚动位置。列表页不会自动选择任何商家。

现有商家详情页改用新的 `merchantDetailFragment` 导航目标。首页、商家列表和搜索结果都调用同一条选择流程：

1. 使用真实商家 ID 调用 `OrderingViewModel.openMerchant(id)`。
2. 如购物车属于另一商家，显示现有的清空购物车确认框。
3. 商家选择成功后导航到 `merchantDetailFragment`。
4. 详情页显示加载状态，菜单返回后再渲染菜品。

详情页不再使用“清粥小菜”或静态菜单兜底。没有选中商家时显示“请先选择商家”并返回列表；菜单为空时显示“该商家暂时没有可售菜品”；接口失败时显示错误和重试入口。

## 后端分页协议

现有 `GET /api/merchants` 保留搜索参数并补强稳定分页：

- `page`：从 0 开始。
- `size`：Android 固定传 4。
- `openOnly=true`：首页与商家 Tab 只读取营业商家。
- 返回 Spring Page JSON，Android 使用 `content`、`number`、`last`、`totalElements`。
- 分页前按商家 ID 升序排序，保证翻页期间不会重复或跳项。

Android 新增通用 `PagedResult<T>` 和 `MerchantFeedViewModel`。首页和商家列表分别创建自己的 ViewModel 实例，但复用同一分页状态机：`items`、`nextPage`、`isInitialLoading`、`isAppending`、`endReached`、`error`。同一页请求未完成时拒绝重复请求，返回结果按商家 ID 去重。

## 评价数据与接口

新增 `merchant_reviews` 表：

- `id`：主键。
- `merchant_id`：关联商家，建立索引和外键。
- `reviewer_name`：演示昵称，不对应真实个人。
- `rating`：1.0–5.0。
- `content`：评价正文。
- `created_at`：评价时间。

新增只读接口：

`GET /api/merchants/{merchantId}/reviews?page=0&size=10`

接口校验商家存在，按 `created_at DESC, id DESC` 返回稳定分页结果。响应包含 `id`、`merchantId`、`reviewerName`、`rating`、`content` 和 `createdAt`。

`data/seed/reviews.json` 为现有 12 家演示商家各提供 3–5 条评价。数据写入数据库并通过接口读取，不在 Android 端硬编码。种子加载器需要支持增量同步，不能因为 `seed_alice` 已存在就跳过新增评价；重复启动不得产生重复数据。

## 商家详情评价交互

“点菜”和“评价”是互斥标签：

- 默认显示点菜区和购物车栏。
- 点击“评价”后隐藏分类、菜单和购物车栏，显示评价列表。
- 首次进入评价时加载第 0 页，接近底部时继续加载。
- 点击“点菜”恢复菜单和购物车栏，不重复加载已经取得的菜单。
- 评价为空、加载失败、加载下一页和全部加载完成都有独立状态。

评价第一版只读，不显示输入框、发布按钮或虚假的“已购买”标识。

## 数据一致性与错误处理

- 商家分页、菜单和评价请求都使用明确的商家 ID。
- 切换商家时立即清空旧菜单展示，避免短暂显示上一家菜单。
- 旧请求晚于新请求返回时，不得覆盖当前商家状态。
- 首屏失败显示重试按钮；追加页失败保留已加载内容，并在列表底部显示“加载失败，点击重试”。
- 后端返回最后一页后不再发送请求，并显示“已经到底了”。
- 未营业商家不出现在首页和商家 Tab，但搜索功能仍可按现有规则决定是否展示。

## 测试与验收

### 后端

- 商家分页顺序稳定、页间无重复，`openOnly=true` 排除未营业商家。
- 评价接口只返回目标商家的评价，顺序和分页信息正确。
- 不存在的商家返回明确错误。
- 种子数据重复加载保持幂等，现有数据库也能补齐新增评价。

### Android 单元测试

- 分页状态机正确处理首屏、追加、重复触发、失败重试、去重和末页。
- 不同商家 ID 分别加载对应菜单，旧菜单不会泄漏。
- 商家详情没有选中商家时不显示默认“清粥小菜”。
- 评价标签切换和只读分页状态正确。

### Maestro

- 首页连续下滑至少加载三页商家。
- 点击两个不同首页商家，分别进入不同详情并看到各自菜单。
- 点击“商家”Tab 首先看到列表，不会自动进入详情。
- 商家列表下滑加载下一页并打开指定商家。
- 详情页点击“评价”能看到后端评价，下滑后继续追加；切回“点菜”恢复菜单。
- 首页只显示“好店推荐”，不再显示距离和定位提示。
